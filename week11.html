02 · 친구 API

친구 요청 저장 방식 비교

연동 전 — Firestore 직접 저장

// 연동 전: Flutter가 친구 요청을 Firestore에 직접 저장함
transaction.set(requestRef, {
  'fromUid': uid,
  'toUid': target.uid,
  'status': 'pending',
  'createdAt': FieldValue.serverTimestamp(),
  'updatedAt': FieldValue.serverTimestamp(),
});

연동 후 — POST /friend-requests

// 연동 후: 친구 코드만 Spring Boot 서버에 전달함
await _api.call('POST', '/friend-requests', {
  'friendCode': target.friendCode,
});

// _api에서 Firebase ID Token을 자동으로 첨부함
// 서버가 요청자·기존 친구·중복 요청 검사 후 저장함
변경 핵심: 앱에서 친구 요청 문서를 직접 저장하는 대신, 서버에 친구 코드 전달 → 인증과 중복 검사 → MySQL 저장으로 역할 분리함
03 · 회원가입 오류

DB 이름과 마이 화면 이름이 일치하지 않음

마이 화면: gangkang49 표시
MySQL: kanghyeon 저장

원인 확인

마이 화면 API 연결 누락이 아니라 회원가입 처리 순서가 겹친 문제였음

Firebase가 로그인 상태를 먼저 알리면서, 입력한 이름 저장이 끝나기 전에 사용자 정보 조회·생성이 실행됨

이후 DB 이름이 수정되지만 마이 화면은 먼저 조회한 이름을 유지함

}

04 · 친구 깨우기 오류

친구 깨우기 기능 테스트 중 문제 발생

발생한 문제

“친구의 알림 수신 기기가 등록되어 있지 않습니다.”

친구 깨우기 버튼 클릭 시 해당 안내 메시지 출력됨

친구 기능은 연동됐지만 실제 푸시 알림은 전달되지 않음

확인 결과

MySQL의 device_tokens 테이블에 저장된 데이터가 없었음

iOS에서 알림용 기기 토큰이 정상적으로 등록되지 않은 문제 확인함

현재 iOS 푸시 설정 및 Apple 개발자 계정 문제로 실제 수신 테스트 보류함

다음 주 Windows에서 Android 앱으로 깨우기 알림 수신 테스트 진행 예정임
