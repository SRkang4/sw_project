러닝 중 좌표 기록

GPS 좌표 필터링과 서버 저장 방식을 구체화함

POST /running-route-points

러닝 중 수집되는 GPS 좌표를 서버에 저장하여 운동 완료 후 러닝 코스를 다시 표시하는 데 사용함.

GPS 좌표 수집
↓
Flutter에서 좌표 필터링
↓
pointOrder / segmentNo 부여
↓
유효 좌표 5개 누적
↓
서버로 한 번에 전송

관련 테이블

테이블 처리 사용 내용
workouts 조회 운동 사용자, 종류, 상태 확인
running_route_points 생성 위도·경도, 측정 시각, segmentNo, pointOrder 저장

담당 클래스

구분 클래스 역할

Repository WorkoutRepository
RunningRoutePointRepository 		운동 조회 및 좌표 저장
요청 DTO RunningRoutePointRequest GPS 좌표 및 관련 정보 전달
응답 DTO RunningRoutePointResponse 좌표 저장 결과 반환

처리 순서

Firebase 인증 확인
↓

↓

↓
IN_PROGRESS 상태 확인
↓
요청 좌표의 필수값 / 형식 확인
↓
running_route_points 저장

예외 상황 및 확인 항목

예외 상황 운동 기록 없음 → 404
다른 사용자 운동 → 접근 거부
러닝이 아니거나 진행 중이 아님 → 저장 거부
중복 좌표 요청 → 중복 저장 방지
확인할 테스트 좌표가 순서대로 저장되는지 확인
재개 후 segmentNo 변경 확인
필수값 누락 / 형식 오류 확인
다른 사용자의 workoutId 저장 차단 확인

GPS 좌표를 그대로 사용하지 않음

GPS 오차로 위치가 순간적으로 튀면 실제로 이동하지 않은 거리가 추가되거나 코스가 이상하게 그려질 수 있어 앱에서 좌표를 한 번 필터링하도록 설계함.

검사 항목 기준 처리
좌표 유효성 위도 -90~90 / 경도 -180~180 잘못된 값 제외
좌표 시각 측정 후 10초 초과 오래된 좌표 제외
중복·역순 직전 좌표보다 시간이 같거나 이전 제외
움직임 센서 정지 상태 3초 이상 좌표 제외
GPS 정확도 accuracy ≤ 10m 초과 시 제외
비정상 속도 15m/s 이상 GPS 점프로 판단하여 제외
거리 계산 GPS 좌표를 직접 가지고 있는 Flutter에서 실시간 거리 계산
5개씩 전송 좌표마다 API를 호출하지 않고 정상 좌표 5개씩 묶어서 전송
일시정지 남은 좌표를 먼저 전송한 뒤 운동 상태를 PAUSED로 변경
pointOrder는 전체 좌표 순서를 관리하고, segmentNo는 일시정지 전후의 서로 연결되지 않은 러닝 구간을 구분함.

문제

러닝 시간이 길어질수록 running_route_points에 GPS 좌표가 계속 쌓이게 됨.

하지만 좌표를 저장하는 이유는 운동 완료 후 사용자의 러닝 코스를 다시 보여주기 위해서였음.

코스의 형태만 유지할 수 있다면 직선상에 겹쳐 있거나 없어도 되는 중간 좌표는 제거해도 되지 않을까?

RDP 알고리즘 적용

곡선이나 다각형을 이루는 수많은 점들을 유지하면서도 점의 개수를 줄여(단순화) 전체적인 형태를 근사화하는 알고리즘

경로의 모양을 유지하면서 불필요한 중간 좌표를 줄이는 방법을 찾아본 결과 Ramer-Douglas-Peucker 알고리즘을 적용하기로 함.

RDP 적용 전

● ─ ● ─ ● ─ ●
      ╲
       ●
        ╲
         ● ─ ● ─ ●

RDP 적용 후

● ───────── ●
         ╲
          ●
           ╲
            ● ───── ●
완료 시 적용 러닝 중에는 복구를 위해 원본 좌표를 유지
segment별 처리 일시정지 전후의 코스가 연결되지 않도록 구간별 적용
distance_m 유지 RDP는 코스 좌표만 줄이고 실제 러닝 거리는 다시 계산하지 않음
RDP는 앱에서 하지 않고 Spring Boot 서버에서 처리함. 완료 시점에는 전체 좌표가 이미 DB에 있기 때문에 앱이 데이터를 다시 받아 계산하고 재전송할 필요가 없음.
